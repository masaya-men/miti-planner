# ツアー計画画面(蛇行グリッド)設計書 (2026-08-11)

## 背景と目的

ハウジングの「ツアー」機能には、現状3つの課題がある。

1. **ツアー内の並べ替えが窮屈**: 探す/お気に入りページ右側の常設トレイパネル(幅300px)でしかツアーの並び順を編集できない。ドラッグ並び替え・固定(ピン)・自動並べ替え自体は既に実装済みだが、50件・100件規模のツアーを組む場合、この細い枠だけでは操作しづらい。
2. **ヘッダーの文言が不自然**: 上部タブの「ツアー」に相当するラベルが `housing.tabs.tour` = 「ツアー中」固定になっており、ツアーを始めていない(計画中の)状態でも「ツアー中」と表示されてしまい違和感がある。
3. **「ツアー」タブが計画中は機能していない**: `/housing/tour` (PC) およびスマホ下部ナビの「ツアー」は、実際にツアーを開始する前(`useHousingTourStore.listingIds` が空)は `TourEmptyState` を表示するだけで、探す/お気に入りページで積み上げたトレイの中身(`useTourTrayStore.trayIds`)とは連動していない。「お気に入りへ」ボタンと住所直接追加欄があるだけの、ほぼ空の画面になっている。

この3つをまとめて解決し、「ツアー」タブを**開始前は大きい版のトレイ(計画画面)として使え、そこからツアー開始もできる**画面にする。

## 確定済みの決定(ユーザー合意・2026-08-11)

| 論点 | 決定 |
|---|---|
| タブ文言 | `housing.tabs.tour` を「ツアー中」→「ツアー」に変更。未開始/計画中/実行中のどの状態でも同じラベル |
| 「ツアー」タブの中身の出し分け | ①実行中(`useHousingTourStore.listingIds.length > 0`)= 今の3パネルUI(不変) / ②計画中(トレイに1件以上、`useTourTrayStore.trayIds.length > 0`)= 新規の計画画面(本設計) / ③空(トレイも0件)= 今の空状態を維持+ボタン追加 |
| 空状態の変更点 | 今の「お気に入りへ」ボタンに加えて「探すへ」ボタンも並べる(トレイへはどちらのページからも追加できるため)。住所から直接追加する欄(ephemeral)はそのまま維持 |
| 計画画面のレイアウト(PC) | 左に固定の詳細パネル(選択中の1件を表示)+ 右に残り全部の領域を使った並べ替えグリッド |
| 左の詳細パネルの中身 | ツアー実行中の現在地カード(`TourShowcasePanel`)と同じ見た目: 写真/動画・ハウジンガーのアイコン+名前・タイトル・コメント(紹介文)。下に「ツアーを開始する」ボタン |
| 左パネルの初期選択 | ページを開いた時点でトレイの1番目の家を自動選択。カードをクリックすると選択が切り替わる |
| 右のグリッドの並び方 | 列を上から下まで並べたら、隣の列は下から上へ、その隣はまた上から下へ…と**ジャンプせず線がつながったまま**蛇行して右へ続く(ジグザグ)。画面に入りきらない分は横スクロール |
| グリッドのカード | 新規デザインはせず、**今のトレイの行カードをそのまま流用**。ただし住所表示は削除し、その分タイトル表示を大きく/広くする |
| 並べ替えの操作方法 | 今と同じ(カード左端のつまみをドラッグ、`@dnd-kit` ベース)。並べ替えると蛇行の接続線は新しい順序に合わせて自動的につなぎ直る |
| ピン留め・効率順ボタン | 今の機能(この位置に固定/効率順に並べる)をそのまま維持。グリッド上部にまとめて配置 |
| 案内文言 | 「ドラッグで並べ替えできます」「ピンで順番を固定できます」という一言案内を、グリッド上部に控えめなグレー文字(色付きの箱にはしない)で常時表示 |
| 住所表示の削除範囲 | トレイの行カードは**共有部品**のため、この変更は探す/お気に入りページの既存の細いサイドバートレイ・スマホの一覧にも同時に反映される(住所抜き・タイトル広め に統一) |
| スマホの計画画面 | 下部ナビの「ツアー」タブ自体が計画画面になる。ただし**蛇行グリッドは使わず、今のトレイ一覧と同じ縦一覧のまま**(画面が狭いため左の詳細パネルも無し) |
| スマホの既存フロート帯(`MobileTourTrayBar`) | 探す/お気に入りページを見ている間に出る件数表示+開始ボタンの役目はそのまま維持。ただし「並べ替え」ボタンは、別シート(`TourReorderSheet`)を開くのをやめて「ツアー」タブへ遷移するように変更(同じ機能の画面を2つ持たないようにする) |

## 現状の実装(前提知識)

- タブ定義の単一ソース: `src/components/housing/shell/housingTabs.ts:15`(`{ key: 'tour', labelKey: 'housing.tabs.tour', path: '/housing/tour' }`)。日本語訳は `src/locales/ja.json:2053`。
- ルーティング: `src/App.tsx:101` の `<Route path="tour" element={<TourNavPage />} />` が全状態(空/計画中/実行中)を1つのページコンポーネントで受けている。
- 「実行中」判定は `useHousingTourStore`(`listingIds`/`currentIndex`/`phase` 等)。0件なら `TourNavPage.tsx:286-300` で `TourEmptyState` を返す実装になっており、これが計画中のトレイ内容と繋がっていない今回の根本原因。
- 「計画中」のトレイは別ストア `useTourTrayStore`(`trayIds`/`pinnedIds`/`manualOrder`)。探す/お気に入り両ページの右サイドバー `TourTray.tsx`(`src/components/housing/browse/TourTray.tsx`)が購読し、幅は `--housing-right-w: 300px`(`src/styles/housing.css:209`)。
- トレイの行き先リスト本体は共有部品 `TourTrayList.tsx`(`src/components/housing/browse/TourTrayList.tsx`)。ドラッグ並び替え(`@dnd-kit/core`+`@dnd-kit/sortable`)・ピン留め・効率順ボタン(`resolveTourOrder` 経由)が実装済み。PC サイドバーとスマホの並べ替えシート(`TourReorderSheet.tsx`)の両方がこれを再利用している。
- 実行中の現在地カード `TourShowcasePanel.tsx`(`src/components/housing/tour/TourShowcasePanel.tsx`)が、写真/動画(`TourLivingMedia`)・ハウジンガーバイライン・タイトル・住所+広さ・紹介文を表示する現行実装。今回の左パネルはこの見た目を計画中(選択中の家)向けに再利用する。
- スマホの浮遊バー `MobileTourTrayBar.tsx` は `trayIds.length > 0` の間だけ表示され、件数+開始+並べ替え(シートを開く)を提供している。

## 変更が必要な範囲

### 1. i18n: タブ文言
`housing.tabs.tour` の値を「ツアー中」→「ツアー」に変更(5言語)。他のキー(`housing.tour.nav.title` 等の「ツアー中(ナビゲーション)」文言)はナビ実行中ページ自体のタイトルなので対象外。

### 2. `TourNavPage` の出し分けロジック変更
`listingIds.length === 0` の分岐を、`useTourTrayStore.trayIds` も見るように拡張:
- 実行中 → 現行のまま
- `trayIds.length > 0`(未実行だが計画あり)→ 新規コンポーネント(計画画面)を表示
- 完全に空 → 現行の `TourEmptyState` を表示(「探すへ」ボタン追加)

### 3. 新規コンポーネント: PC計画画面
- 左: 選択中の家の詳細(`TourShowcasePanel` 相当の見た目を流用/共通化)+「ツアーを開始する」ボタン(押すと現行の開始処理: `orderTourStopIds` → `setListings` → `start` 等、既存の開始フローを踏襲)。
- 右: 蛇行グリッド。列ごとに上下交互の向きで、行き先カード(住所なし版の `TourTrayList` 行)を配置し、SVGまたはCSSで接続線を描画。ドラッグ確定時に線を再計算。
- グリッド上部: 案内文言(グレー、箱なし)+ ピン留め/効率順ボタン。

### 4. 新規/変更コンポーネント: スマホ計画画面
- 縦一覧のみ(左パネル無し)。既存 `TourTrayList` をそのまま画面いっぱいに表示 + 開始ボタン。
- `TourReorderSheet` は用途を終えるため撤去し、`MobileTourTrayBar` の「並べ替え」ボタンは `/housing/tour` への遷移に置き換える。

### 5. 行カードの表示変更(共有部品)
`TourTrayList.tsx` の行(`TourTrayRow`)から住所表示を削除し、タイトル表示を拡張。タイトル未入力時は現行通り住所をタイトル代わりに表示するフォールバックは維持(空欄にはならない)。この変更は探す/お気に入りページの既存サイドバートレイにもそのまま反映される。

### 6. 空状態の変更
`TourEmptyState.tsx` に「探すへ」ボタンを追加(「お気に入りへ」ボタンと並べる)。住所から直接追加する欄は現行のまま維持。

## 非対象・据え置き事項

- ツアー実行中(3パネルUI: `TourShowcasePanel`/`TourNavMap`/`TourProgressPanel`)の画面・操作には手を入れない。
- 地域跨ぎブロック(`canAddToTour`/`tourAnchorRegion`)、住所登録なし一時追加(ephemeral)の仕組み自体は変更しない。
- 並べ替えの中身(ドラッグ/ピン/効率順のアルゴリズム)は変更しない。見せ方(蛇行グリッド)だけを追加する。
- パフォーマンス(100件規模でのDOM描画・接続線再計算のコスト、仮想化の要否)は実装計画の段階で検討する。現行のトレイ一覧も仮想化していないため、まずは同水準で実装し、実機で問題があれば対処する。

## テスト方針(実装計画で詳細化)

- `TourNavPage` の出し分けロジック(実行中/計画中/空の3分岐)の単体テスト。
- 新規計画画面: 初期選択(1番目自動選択)・カードクリックで選択切替・ドラッグ後の接続順序が保つべき順序と一致すること。
- `TourTrayRow` の表示変更(住所非表示・タイトルフォールバック)を既存テストに反映。
- スマホ: `MobileTourTrayBar` の「並べ替え」ボタンが `/housing/tour` へ遷移することの確認。

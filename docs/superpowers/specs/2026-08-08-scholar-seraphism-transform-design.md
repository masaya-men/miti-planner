## 1. 目的 / 背景

2026-08-08 セッションでマニフェステーション(スキル定義)を追加済み(`28bd5001`)だが、実際の「セラフィズム発動中は鼓舞激励の策/意気軒高の策の代わりに強制的にマニフェステーション/アクセッションになる」という自動変化の仕様がまだ未実装。現状は両方が**独立した選択肢**としてスキル選択パネルに並んで表示されるだけで、ユーザーが手動でどちらを置くか選ばないといけない。

ゲーム内では、セラフィズム発動中は鼓舞激励の策/意気軒高の策のホットバーアイコン自体がマニフェステーション/アクセッションに置き換わる(ボタンは1つ、中身が変わる)。LoPo でも同じ体験にする。

設計検討の過程で、ユーザーのゲーム知識を公式ソース([na.finalfantasyxiv.com/jobguide/scholar](https://na.finalfantasyxiv.com/jobguide/scholar/)、[ffxiv.consolegameswiki.com](https://ffxiv.consolegameswiki.com/wiki/Recitation))で裏取りし、関連する2件の実装ズレも本タスクで一緒に直すことが確定した(詳細は §2.2, §2.3)。

## 2. 確定仕様

### 2.1 自動変化ロジック(本題)

- 判定条件: 「鼓舞激励の策 / 意気軒高の策を**配置しようとしている時刻**に、セラフィズム(`seraphism`)が効いているか」。既存の `requires` 窓判定(例: ニュートラルセクト中のみ使用可、[resourceTracker.ts:470-505](../../../src/utils/resourceTracker.ts#L470-L505))と同じ「配置時点のスナップショット」方式に揃える。**後からセラフィズムの位置をタイムライン上でずらしても、既に置いた側は変化しない**(ゲームも「使った瞬間の状態」で確定する仕様と一致)。
- 該当時刻でセラフィズムが有効なら、鼓舞激励の策ボタンは**マニフェステーション定義そのもの**(id・name・icon・shieldPotency 等すべて)にすり替えて表示・選択させる。意気軒高の策 → アクセッションも同様。
- マニフェステーション/アクセッションの定義に `hidden: true` を追加し、選択パネルの独立ボタンとしては**常に非表示**にする(既存 `Mitigation.hidden` フィールド・既存フィルタ実装をそのまま利用、[types/index.ts:83](../../../src/types/index.ts#L83) / [MitigationSelector.tsx:146](../../../src/components/MitigationSelector.tsx#L146))。
- ソート順(`getMitigationPriority`)は元の id(鼓舞激励の策/意気軒高の策)を基準にする。すり替え後の id でソートすると一覧内の表示位置が変化前後で飛んでしまうため、**フィルタ→ソート→すり替え**の順に処理を並べる(現状は フィルタ→すり替え→ソート の順)。
- 同じすり替えロジックを **PC 用パネル (`MitigationSelector.tsx`)** と **スマホ用パネル (`Timeline.tsx` 内の埋め込み選択 UI)** の両方に適用する(既存の「サモン・セラフィム中は光の囁き/フェイイルミネーションの名称だけ変える」処理が PC 側にしか実装されておらずスマホは対象外、という前例があるが、今回は数値(潜在力)も変わるため両方必須)。

### 2.2 展開戦術の対象拡張(付随修正・公式確認済み)

- 展開戦術は「鼓舞(Galvanize)」状態を周囲に広げる技。マニフェステーションも鼓舞激励の策と同じく鼓舞を付与するため、セラフィズム中に貼ったマニフェステーションのバリアも展開戦術のコピー元候補に含める必要がある。
- 意気軒高の策/アクセッションは鼓舞ではない別種のバリアのため、展開戦術の対象外のまま(現状通り、変更不要)。
- 修正箇所: `MitigationSelector.tsx` 内の `copiesShield` 候補フィルタ(2箇所、[L204-208](../../../src/components/MitigationSelector.tsx#L204), [L494-498](../../../src/components/MitigationSelector.tsx#L494))。`l.mitigationId === mitigation.copiesShield` の判定に加えて、`copiesShield === 'adloquium'` のときは `l.mitigationId === 'manifestation'` も候補に含める。

### 2.3 秘策の対象修正(付随修正・公式確認済み)

- 公式仕様: 秘策が確定クリティカルを保証するのは「鼓舞激励の策・意気軒高の策(旧: 士気高揚の策)・不撓不屈の策・深謀遠慮」の4つのみ。マニフェステーション/アクセッションは明記されておらず対象外。
- 現状の LoPo (`Timeline.tsx` の被ダメ計算, [L2112-2128](../../../src/components/Timeline.tsx#L2112)) は `def.isShield` の真偽だけで判定しており、学者のバリア技(コンソレイション/アクセッション/マニフェステーション含む)全般に確定クリティカルを適用してしまっている。これは今回のタスク以前からのズレだが、鼓舞激励の策がマニフェステーションへ自動変化するようになると表面化しやすくなるため、本タスクで一緒に直す。
- 修正方針: 確定クリティカル付与および「秘策の1回消費判定」の対象を `adloquium`(鼓舞激励の策) / `concitation`(意気軒高の策・レベル92以上) / `succor`(意気軒高の策の旧名・士気高揚の策・レベル91以下)の3 id に限定する。コンソレイション・アクセッション・マニフェステーションは対象外になる。
- 不撓不屈の策・深謀遠慮は `isShield: false` のため、この if ブロック自体を通らない(別経路)。今回のバリア判定コードの対象外のままで良い(公式仕様上は秘策の対象だが、そもそもバリアではなく通常回復であり、今回touchするコードパスに存在しないため変更不要)。
- SGE のゾーエは対象外(公式確認済み: 「次の回復魔法」全般に効く仕様のため、現状の広い判定のままで正しい。学者の秘策とは仕様が異なる)。

## 5. テスト方針

- 既存テストで `MitigationSelector` / セラフィム関連の回帰がないか確認(`seraphFairyLockout.test.ts` 等)。
- 新規: セラフィズム有効時に鼓舞激励の策 → マニフェステーション、意気軒高の策 → アクセッションとして選択・配置されることの単体テスト(PC/スマホ両パネル)。
- 新規: 展開戦術がマニフェステーションのバリアをコピー候補に含めることのテスト。
- 新規: 秘策使用中の確定クリティカルが鼓舞激励の策/意気軒高の策のみに適用され、コンソレイション/アクセッション/マニフェステーションには適用されないことのテスト。

# 同じ秒に 3 つ以上の攻撃 + 攻撃の数に応じた行の高さ — 設計書

- 日付: 2026-09-26
- 状態: 設計確定(ユーザー承認済み: ①見た目と操作 / ②作りの中身 / ③安全策と確認)
- 対象: 軽減表のタイムライン(PC 表・スマホ表)、FFLogs 取り込み
- 前提コード: origin/main `504ff28e`
- 方針: 内部の作りは「長く安定して、直しやすい」ことを最優先(ユーザー明言)。テストは軽め(ユーザー指示)

## 1. 目的

1. 同じ秒の敵の攻撃を、いくつでも表に表示する。
   - 現状: 3 つ目以降も保存・計算はされるが、PC 表もスマホ表も 2 つまでしか描かない(見えないのに計算される攻撃が作れてしまう)。
2. PC の行の高さを攻撃の数に応じて変える。攻撃 1 つの行を低くし、一覧性を上げる。
3. 追加の入口を分かりやすくする(攻撃 1 つの行の下にある細い「+」を廃止)。

## 2. 決定事項(ユーザーから見える動き)

### 2.1 PC 表

- **行の高さ**: 1 段 = 25px(今の行 50px の半分 = 今の「2 つ並び」の 1 段)。行の高さ = 25px × max(1, その秒の攻撃数)。
  - 攻撃なし(軽減だけの行・空きの秒)= 25 / 1 つ = 25 / 2 つ = 50(今と同じ)/ 3 つ = 75 / 4 つ = 100
- **並び順**: 今のまま(MT → ST → 全体。同じ種類の中は登録順)。
- **各段の中身**: 今の 2 つ並びの段と同じ(種別・攻撃名・対象・RAW・TAKEN)。段の区切り線(行の罫線表示が ON のとき)は最後の段以外の下。
- **時刻の列**: 行の縦中央に 1 つ。
- **軽減アイコン**: 行の最上段(1 つ目の攻撃の段)の縦中央に置く。
  - 攻撃 2 つの行では、今の「2 つの真ん中」から上の段へ移る(承認済みの見た目の変更。行が高いときにアイコンが真ん中だと、1 つ目の攻撃にかかっていないように見えるため)。
- **効果時間の帯**: アイコン中央から「効果がかかる最後の秒の行の下端」まで(今と同じ意味)。行が伸びれば帯も伸びる。
  - 途中の切れ目(バリア使い切り・上書き負け・ホロスコープ / アーサリースター / WD)も今と同じ意味を保つ。
- **追加のしかた**:
  - 攻撃の段にホバーすると、右からコピーが出る。その左隣に「+」も同じ動きで出す。ツールチップは既存キー `timeline.event_add_here`(5 言語あり)。
  - 「+」の動き = 今の細い「+」と同じ(`onAddEventClick` → コピー中は貼り付け / AA モード中は AA 追加 / それ以外はイベント追加モーダル)。
  - 攻撃 1 つの行の下の細い「+」は廃止。
  - 空の行の「+」(チュートリアルの目印 `add-event-btn` / `add-event-btn-11` 付き)と、攻撃名クリックのメニュー(編集 / この時間にイベントを追加 / 削除)はそのまま。
  - 右クリックでの追加は作らない(種別アイコンの右クリック = デバフ軽減不可の切替と紛らわしいため)。
- **AA モード**: 件数に関係なく AA を追加する(今の「同じ秒に 2 つあると AA モードを解除してモーダルを開く」をやめる)。
- **空の行を隠す設定**: 隠す / 隠さないの判定は今のまま。隠さない場合、空きの秒も 1 段。
- **軽減アイコンの大きさ**: 今の 24px のまま実装する。ユーザーがローカル確認で実物を見て決める(定数 1 か所で変えられる作りにする)。

### 2.2 スマホ表

- 1 枚 60px のカードを攻撃の数だけ並べる(今の 2 枚決め打ちを N 枚に)。攻撃なしは 1 枚。
  - 行の高さの式は PC と同じ(1 段 = 60px × max(1, 攻撃数))。スマホの見た目の高さは今と変わらない。
- 長押し → **押したカードの攻撃**のメニューを開く(今は常に 1 つ目の攻撃が開く不具合を修正)。
- 同じ秒の 2 枚目以降は、今の 2 枚目と同じ見た目(時刻を薄く)。最後のカード以外は下の区切り線なし。

### 2.3 FFLogs 取り込み

- 同じ秒の攻撃をずらさず、本当の秒のまま取り込む。次の 3 つのずらしを廃止する。
  - 同じ秒に 3 つ以上 → 3 つ目以降を +1 秒
  - タンクへの攻撃と全体攻撃が同じ秒 → 全体攻撃を +1 秒
  - 全体攻撃と AA が同じ秒 → AA を +1 秒
- 1 秒あたりの攻撃数に上限は設けない。
- 取り込み済みの軽減表は変わらない(取り込む時だけの処理のため)。

### 2.4 変えないもの

- 保存データの形(`TimelineEvent` に項目を足さない)。
  - 共同編集・共有・バックアップと互換。古い版を開いたままの人の画面では、3 つ目以降が表示されないだけ。
- ダメージ計算の順番(同じ秒の中は登録順のまま)。
- MIL-SPEC テーマは同じ表を埋め込んでいる(`MilspecWorkspace` の children)ので、自動で同じ変更が入る。

## 3. 作りの中身

### 3.1 行の配置係 `src/components/timeline/rowLayout.ts`(新規)

画面を持たない純粋な計算。表の縦方向の位置に関する答えは、すべてここから出す。

```ts
export const ROW_UNIT_PX = { pc: 25, mobile: 60 } as const;
export const MITI_ICON_PX = 24; // PC の軽減アイコン(ユーザーが実物を見て決める)

export interface RowLayoutInput {
  times: readonly number[];                  // グリッドの秒の並び(今の gridLines = -10〜戦闘時間)
  eventCountAt: (t: number) => number;
  hasMitigationStartAt: (t: number) => boolean; // autoHidden を除く軽減の開始
  hideEmptyRows: boolean;
  maxPopulatedTime: number;                  // 今と同じ算出(攻撃と軽減の最大時刻)
  forceVisibleTimes?: ReadonlySet<number>;   // チュートリアル create-6-add-event の 0 秒
  unitPx: number;
}

export interface RowBox { time: number; top: number; height: number; visible: boolean }

export interface RowLayout {
  unitPx: number;
  rows: readonly RowBox[];                      // times と同じ順
  totalHeight: number;                          // 可視行の高さの合計
  timeToY: Map<number, number>;                 // 今の timeToYMap と同じ意味(読み取り専用として扱う)
  sortedTimeY: [number, number][];              // 今の sortedTimeYRef と同じ意味
  topOf(t: number): number;
  bottomOf(t: number): number;
  timeAtY(y: number): number;
}

export function computeRowLayout(input: RowLayoutInput): RowLayout;
```

- **可視判定**(今の 2 か所の判定と同じ): `!hideEmptyRows || 攻撃あり || 軽減開始あり || t === maxPopulatedTime + 1 || forceVisibleTimes に含まれる`
- **高さ**: 可視 → `unitPx × max(1, 攻撃数)`、不可視 → 0
- **timeToY**: 各秒の行の上端。不可視の秒は「その時点の累計」= 直前の可視行の下端 = 次の可視行の上端(今の timeToYMap と同じ意味。メモ・リモートカーソルの `timeSecToY` / `yToTimeSec` / `reanchorScrollTop` はこの意味に依存しており、そのまま正しく動く)
- **topOf(t)**: グリッド内 = timeToY。グリッドより後 = 最後の行の下端 + (t − 最後の秒 − 1) × unitPx。グリッドより前 = 0
- **bottomOf(t)**: topOf(t) + その行の高さ(不可視なら高さ 0 → 直前の可視行の下端)
- **timeAtY(y)**: y を含む可視行の秒(行の範囲は上端を含み下端を含まない)。最初の可視行より上 → 最初の可視行、最後より下 → 最後の可視行。可視行が 1 つも無い場合は times の先頭(times も空なら 0)

軽減アイコンと帯の位置も同じファイルに置く(今の固定値 +13 / 12 / +24 / −8 を置き換える。均一な 50px 行では今と同じ位置になる式):

| 用途 | 式 | 今の式(50px 行) |
|---|---|---|
| アイコンの上端(行内) | `(unitPx − MITI_ICON_PX) / 2` | 13 |
| 帯の始点 | `topOf(開始) + unitPx / 2`(アイコン中央) | top + 13 + 12 |
| 帯の終点 | `bottomOf(最後にかかる秒) − 1` | map(秒) + 24 + 25 |
| 使い切り・上書き負けの切れ目 | `bottomOf(その秒) − 1` | cutY + 24 + 25 |
| 親子の切れ目(ホロスコープ等) | `topOf(子の秒) + アイコン上端 + 4` | cutY − 8 + 25 |

補足: 空の行を隠すモードで「帯の終わりの秒が不可視」のとき、`bottomOf` は直前の可視行の下端を返す。今の「直前の可視行へ切り詰める」処理と同じ結果になる。

### 3.2 利用側(全部 rowLayout 経由にする)

**Timeline.tsx**

- 描画ループと「表全体の高さ」の二重計算(今は 2 か所に同じ可視判定。しかもスマホの 2 件行を高さ側が 1 段分しか数えない食い違いがある)を、`computeRowLayout` 1 回(`useMemo`)に一本化する。`timeToYMapRef` / `sortedTimeYRef` にはその出力を入れる。
- `pixelsPerSecond`(PC 50 / スマホ 60)を廃止し、`rowUnitPx`(PC 25 / スマホ 60)と rowLayout に置き換える。線形の計算を 1 つも残さない(残ればコンパイルエラーで気づける)。
- 「空の行を隠す設定でなければ割り算」の 4 か所 → rowLayout:
  - 軽減の時刻逆算(`getTimeFromY`)
  - ドラッグのスナップ先
  - リキャスト行の同期
  - 競合矢印の Y
- 「対応表優先 + 割り算フォールバック」の箇所 → `topOf` / `bottomOf`:
  - 帯の `getMappedY`
  - 範囲選択プレビュー
  - フェーズ帯・ラベル帯
  - ジャンプ
  - スマホのフェーズラベル同期
- 軽減アイコン(`MitigationItem`)の固定ずらし量 → 3.1 の位置の式。
- **ドラッグのスナップ**: アイコン中央を含む行へ。均一な行では今と同じ動きになる。
- **帯クリックの配置**: クリック位置を含む行へ。今は行の下半分をクリックすると次の秒になるずれがあり、これも直る。
- AA モードの件数制限(`existingEvents.length < 2`)を削除する。
- スマホ: 2 枚ハードコードを `max(1, 攻撃数)` 枚のループにする。各カードの top は「行の top + i × 60」、`hideBottomDivider` は最後以外。

**TimelineRow.tsx(PC)**

- `height` prop を追加し、`h-[50px]` と `contain-intrinsic-size: auto 50px` を置き換える。memo の比較関数にも `height` を追加する。
- 攻撃列・RAW 列・TAKEN 列の「1 件 / 2 件」分岐(今は 3 列でそれぞれ別実装)を、「N 件を段で並べる」1 通りに統一する(0 件は今の空行「+」)。
  - 段の並べ方の部品と、ダメージ表示(致死判定の色分けを含む)の部品を切り出して、重複をなくす。
- 細い「+」を削除する。ホバーで開く領域を [+][コピー] にする(幅 `w-8` → `w-16`)。「+」は `stopPropagation` して攻撃名クリックのメニューを開かない。

**MobileTimelineRow.tsx**

- 長押しで `events[eventIndex]` を渡す。
- `isSecondEvent` prop を廃止し、`eventIndex > 0` で判定する(memo の比較関数も合わせる)。

**fflogsMapper.ts**

- `resolveSchedulingConflicts` とその呼び出しを削除する。
- 旧設計書 `2026-04-05-fflogs-import-v2.md` の Step 11 に廃止の注記を入れる。

**mobileEffectBar.ts**: 変更なし(1 カード 60px の前提は変わらない)。引数の `pixelsPerSecond` には `rowUnitPx`(スマホ 60)を渡す。

> **2026-09-27 追記(実装時の判断)**: 帯の終点だけは変更した。最後にかかる秒に攻撃が複数ある(カードが縦に並ぶ)ときは、帯をその秒の最後のカードまで伸ばす(§2.1「帯 = 最後にかかる秒の行の下端まで」をスマホでも満たすため・commit 6964569b)。
> **2026-09-28 追記(ユーザー承認)**: 帯の下端を「最後のカードの下端 − 1px」にそろえた(PC の「行の下端 − 1」と同じ)。以前は定数の組み合わせ(24 + 38 = 62 > カード 60px)で、次の秒のカードに 2px はみ出していた。

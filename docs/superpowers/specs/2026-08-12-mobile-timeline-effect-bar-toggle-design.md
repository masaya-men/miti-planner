# モバイル軽減表: スクロール中だけ「エフェクト棒」表示に切り替える — 設計書

## 1. 目的 / 背景

PC版の軽減表には、軽減アイコンの真下に効果の残り持続時間ぶん伸びる色付きの棒(「エフェクト棒」、[Timeline.tsx:575-591](../../../src/components/Timeline.tsx#L575-L591))が表示される。効果の開始時刻・持続時間が縦方向の長さとして視覚化され、どのメンバーの効果がいつまで続くか一目でわかる。

モバイル版は今回のレイアウト刷新で、軽減アイコンを「使用者ごとにグルーピングした専用行」([MobileTimelineRow.tsx:81-123](../../../src/components/MobileTimelineRow.tsx#L81-L123) `MitiIcons`)として各行の2行目に表示する形に変更済み。この専用行は「効果が続いている間、該当行すべてに同じアイコンを繰り返し表示する」ことで持続時間を表現しているが、PC版のような「1本の棒が伸びる」視覚的インパクトはない。

今回、モバイル版でもPC版の「エフェクト棒」を体験できるようにしたい。ただし今の専用行のレイアウト(密度重視・画面幅ぴったり)は気に入っているため変更したくない、という制約がある。

## 2. 確定した体験(UX)

- **静止時(スクロールしていない間)**: 今の見た目のまま。軽減アイコンがメンバーごとにグルーピングされて専用行に並ぶ(変更なし)。
- **スクロール中**: 専用行に並んでいたアイコンがふわっと消え、代わりにPC版と同じ「アイコン+下に伸びる色の棒」がその軽減が置かれた時刻を起点に表示される。メンバーごとの固定位置は用意せず、今アクティブな効果だけを隙間なく詰めて並べる(詳細は3.3)。
- **スクロール停止**: 棒がふわっと消え、また専用行のアイコン表示に戻る。
- 1行目(時間・攻撃名・ダメージ)は常時変更なし。切り替わるのは2行目相当の表示だけ。
- 棒の一番上にはPC版と同じく軽減アイコンを乗せる(色の棒だけにはしない)。

## 3. 技術方針

### 3.1 全体構成

専用行内のDOM(行ごとに独立したflexレイアウト)に棒を描画すると、行をまたいで同じ横位置を保てない(行ごとにその時アイコンを置いた人だけが詰めて並ぶ構造のため)。そこで、PC版の「エフェクト棒」がそうしているのと同じように、**タイムライン全体のスクロールコンテナに対して絶対配置される、行をまたいだ1枚のオーバーレイ層**として棒を描画する(新規コンポーネント、仮称 `MobileEffectBarLayer`)。専用行(`MitiIcons`)側は一切変更しない。

このオーバーレイは常時マウントしておき、CSSの透明度切り替え(後述3.5)で見え隠れさせる。React再レンダリングを毎スクロールフレームで発生させないため。

既存のモバイル専用UIと同じく`md:hidden`相当でPC版には一切影響しない範囲に限定する(PC版のエフェクト棒描画・列詰めロジックは今回完全に触らない)。

### 3.2 縦位置(時間→ピクセル)の計算

PC版が使っている考え方をそのまま流用する(コピーではなく同じロジックを再実装。PC版は列詰めロジック([Timeline.tsx:3407-3421](../../../src/components/Timeline.tsx#L3407-L3421) 等)と密結合しているため、モバイル用に同じ計算式だけを切り出す):

- 開始Y: `timeToYMap`(圧縮表示 `hideEmptyRows` 時の可視行マッピング。範囲外は `pixelsPerSecond` で外挿)を使って `mitigation.time` をYに変換する([Timeline.tsx:3473-3480](../../../src/components/Timeline.tsx#L3473-L3480) の `getMappedY` と同じ考え方)。
- 終了時刻のクリップ: `effectiveEndTime`([Timeline.tsx:3483-3500](../../../src/components/Timeline.tsx#L3483-L3500))と同じルールを適用する。`hideEmptyRows` で終了時刻が空行に落ちる場合は直前の可視行に切り詰め、さらにタイムライン末尾(`maxTime`)でもクリップする。
- 高さ = 終了Yと開始Yの差。

これらの値は既にモバイル行の`top`計算でも同じ`timeToYMap`/`pixelsPerSecond`が使われているため、モバイル行の縦位置とズレは生じない想定。

### 3.3 横位置(詰めて並べる・メンバー固定レーンなし)

ブレスト当初は8人固定レーン(メンバーごとに専用の横位置を予約)案を検討したが、以下の理由で不採用とし、**「今アクティブな効果だけを隙間なく詰めて右寄せで並べ、入りきらない分は優先度の低いものから表示しない」**方式に変更した。

- 固定レーンだと、誰も使っていないメンバーの分まで常に横幅を確保してしまい無駄が多い。
- タンク・ヒーラーとDPSで表示個数に差をつけようとすると(検討時の試算: TH4個/DPS1個 or TH3個/DPS2個)、個数を決め打ちする必要があり、実際の使用状況(全員が上限まで使うことは稀)に対して過剰な予約になる。
- この演出はスクロール中だけの「遊び」要素であり、常時のメンバー識別性より、実際に効いている効果を賑やかに見せる方を優先したいというユーザーの意向による。

**具体的な並べ方**:

- 表示アイコンは現状より小さくする(既存`MitiIcons`の22pxに対し、約2/3の15px程度)。棒の太さ(4〜5px程度)はアイコンサイズに依存させず、PC版同様アイコンより細い一定幅を保つ(PC版もアイコン24pxに対し棒6pxで別サイズ、[Timeline.tsx:580](../../../src/components/Timeline.tsx#L580))。
- 優先順位は`PARTY_MEMBER_IDS`順(MT→ST→H1→H2→D1→D2→D3→D4)。ある軽減が**開始する瞬間**に、その時点で他にアクティブな軽減が使っている位置と重ならない、右端に一番近い空き位置を1つ割り当てる(PC版の同一メンバー列内での重なり回避ロジック[Timeline.tsx:3407-3421](../../../src/components/Timeline.tsx#L3407-L3421)と同じ「衝突回避で位置を詰める」考え方を、メンバー列の制約なしに全体に適用する)。
- 一度割り当てた位置は、その軽減の効果が終わるまで固定する(=スクロール中、1本の棒は横にジグザグせずまっすぐ下に伸びる)。
- 画面の横幅に対して詰め切れなくなった場合、優先順位が低い(=`PARTY_MEMBER_IDS`の後ろの方=DPS)ものから表示をやめる。非表示になった軽減は、止まっている時の専用行アイコン表示には引き続き通常通り表示される(棒の演出にだけ出てこない)。

### 3.4 置ける数への影響なし

この上限・優先順位はあくまで「スクロール中の棒の演出」の表示にのみ影響する。軽減の配置(追加パネル・配置数)自体には一切制限をかけない。止まっている時の専用行アイコン表示(`MitiIcons`)も上限なし・全件表示のまま変更しない。PC版のリキャスト行([RecastRow.tsx](../../../src/components/RecastRow.tsx) の`LIMIT_TH`/`LIMIT_DPS`)も同様に「表示だけ絞る、配置数は無制限」という考え方が既にあり、それを踏襲する。

### 3.5 スクロール検知と表示切り替え

このアプリには既に「特定状態のときだけ親コンテナに`data-*`属性を立て、CSS側で見た目を変える」パターンが複数ある(例: `data-myjob-highlight`、`data-record-mode`。[Timeline.tsx](../../../src/components/Timeline.tsx) 内 `MyJobHighlightAttrBridge` / `RecordModeAttrBridge` 相当)。同じパターンに乗せる:

- スクロールコンテナの既存スクロールイベント(PC版の`syncRecastRow`と同じ`container.addEventListener('scroll', ...)`、[Timeline.tsx:1437-1469](../../../src/components/Timeline.tsx#L1437-L1469) 付近)に相乗りし、モバイル版でも同じイベントで発火する軽量ハンドラを追加する。
- スクロールイベントが来たら即座に`data-mobile-scrolling="1"`を立て、最後のイベントから約150ms経過したら(setTimeoutでデバウンス)`data-mobile-scrolling`を外す。150msは初期値。実機確認しながら微調整する。
- CSS側で、`[data-mobile-scrolling="1"]`のとき専用行(アイコン)のopacityを0に、オーバーレイ層のopacityを1にする(逆は初期値のまま)。`transition-opacity duration-150〜200`程度でクロスフェード。
- オーバーレイ層は`pointer-events-none`(スクロール中の操作を妨げない。棒自体はタップ・ドラッグ操作の対象外とする)。

### 3.6 色・除外ルール

PC版と揃える:

- 色は既存の`getMitigationColorClasses(def?.jobId, mitigation.ownerId, partySortOrder)`([Timeline.tsx:120](../../../src/components/Timeline.tsx#L120))をそのまま使う。
- `mitigation.duration <= 1`(瞬発効果)または`def?.copiesShield`(展開戦術でコピーされた側)は棒を表示しない([Timeline.tsx:576](../../../src/components/Timeline.tsx#L576) と同じ条件)。

## 4. 対象ファイル

- `src/components/Timeline.tsx` — モバイル用オーバーレイ層(`MobileEffectBarLayer`)の新規コンポーネント追加、スクロールコンテナへのスクロールリスナー追加(`data-mobile-scrolling`属性の付け外し)、`timelineMitigations`から棒用ジオメトリ(開始Y/高さ/横位置の詰め込み割り当て/色/アイコン、3.3節のロジック)を導出するロジック。
- `MobileTimelineRow.tsx` — 変更なし(専用行`MitiIcons`はそのまま。CSS側のopacity切り替えのみ影響)。
- `src/index.css` または該当コンポーネント内 — `data-mobile-scrolling`によるopacityクロスフェードのCSS追加。

## 5. 非目標(今回やらない)

- PC版のエフェクト棒表示ロジック・列詰めアルゴリズム自体の変更。
- モバイル専用行(`MitiIcons`)のレイアウト・アイコンサイズ・余白の変更(既存調整を維持)。
- 棒のドラッグ移動・タップ削除などの操作対応(表示のみ、`pointer-events-none`)。
- 競合(CDかぶり)表示(`conflictingIds`)のモバイル対応。TODO記載の通り、これは本タスク完了後の別タスク。

## 6. テスト方針

- 主に実機(iPhone)でのローカル確認(`npm run dev -- --host`)。スクロール開始/停止での表示切り替え、棒の縦位置がPC版の考え方と矛盾しないこと、同時アクティブ数が多い場面でDPSから順に非表示になり画面幅をはみ出さないことを目視確認する。
- `hideEmptyRows`(圧縮表示)ON/OFF両方で棒の位置がずれないか確認。
- 既存のモバイルタイムライン関連テスト(`Timeline.layout.test.tsx`等)に回帰がないことを`vitest`で確認(変更ファイルに絞って実行)。

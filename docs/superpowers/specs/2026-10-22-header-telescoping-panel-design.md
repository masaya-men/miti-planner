## 1. 目的(なぜ)

今のヘッダーは 1189px 基準で描かれ、区画幅 MW が広がると x=700 の縦線(`HDR_FRAME.sx`、`src/components/military/headerGeometry.ts:25`)より右の点が動く。そのため H3 計器板の中央(`headerGeometry.ts:75-80`)と H5 段の継ぎ目(`headerGeometry.ts:86-92`・`:116`)の**金属が横に伸びる**。1489 の画面ではサイドバーを閉じると 276px 伸びる(見本 v3 の「今」の画像)。masaya: 「パネルを 2 重に重ねているデザインにもともとしておいて、下に収納されていた金属パネルが出てくる形にすれば金属が伸びるように見えない」。

## 2. ゴール / やらないこと / 失敗とみなすこと

ゴール
- どの区画幅でも、ヘッダーの金属(上の板)は 1189 基準の形のまま伸びない。広がった分は「右の板に付いた下の板(エキスパンドメタル)」が上の左の板の下から現れて埋める。
- 下の板は、見本 v3 の質感(厚い鋼の網・溶接した平鋼の枠・理由のある汚れと傷・網の奥で光る基板)を、本物の装甲エンジン(`armor/*`)の仕組みの中で描く。本物の MIL-SPEC 部品の隣に置いて浮かない。
- 開閉の動き(`relayout.ts`)は今の 2 段階のまま。切れ目が段違い(700/714/683)になるので、複製の切り分け線もそれに合わせる。
- 網の穴から見えるのは、アプリの本物の背景動画 + 暗幕(`src/styles/military.css:1278-1280`、`rgba(6,8,10,0.88)`)。基板の光は暗幕より手前(筐体の中)なので暗幕に影響されない。

やらないこと
- 「みんなの軽減表」ボタンの領域(`headerGeometry.ts:121,131`・`PartyOps.tsx:106-108`)の中身を変えること。別件で masaya が「ジョブ表示切替+スプシモード切替を置く」案を検討中(未確定)。本書はその領域の**左**に下段の切れ目 683 があるという前提だけを置く(§3 D7)。
- 暗幕の値を変えること(0.88 のまま。`milspecPower.css:7` の電源 off 時の値もそのまま)。
- 通気口・フッター・タイムラインの開閉(Task 5/6 で実装済み)の作り直し。ヘッダーの継ぎ目の形だけが変わる。
- 標準テーマ。

失敗とみなすこと(動いても不合格)
- 上の板・下の板のどこかが伸びて見える(網の目の間隔・枠・レール・基板の部品の大きさが MW で変わる)。
- 開閉の途中に、下の板の窓の中に「上の板の切れ端」が静止して見える(§3 D5 の段違い継ぎ目を inset の 1 本線で代用すると、上段 700〜714 / 下段 683〜700 に 14px/17px の切れ端が出る)。
- 右端基準の部品(時計・H4 一式・軽減表・歯車・SORT)が開閉で 1px でも動く。着いた後の位置合わせ。
- 1489 の画面でサイドバーを開いたとき、下の板が見える(= 2 枚の上の板の切れ目が合わさっていない)。
- 基板の光の粒が、ほかの経路(`fx/engine.ts` の AMB の抽選)の頻度を薄める。
- 静止中(開閉もホバーもしていない)に、ヘッダー区画が毎フレーム描き直される(ぼかしマスクやパターンが毎フレーム再計算される作りは不可)。
- ライトテーマ(`military.css:282-318` の `--ma-*`)で下の板が真っ黒 / 真っ白になる。
- 動きを減らす設定で光の粒が走る。

## 3. 決まったこと(実コードに結びつける)

### D1. 上の板の切れ目(区画座標・1189 基準)と、左右の半分

| 帯 | y | 切れ目 x | 根拠 |
|---|---|---|---|
| 外枠(chassis)上 | 0〜4 | 700 | 今の伸縮線 `HDR_FRAME.sx`(`headerGeometry.ts:25`) |
| 上段 H3 | 4〜48 | **714** | ランプ NET の文字の右端 ≈ 708(`MeterPanel.tsx:155-160`、実測)と DTG の文字/時計 x=721(`headerGeometry.ts:149-150`、`MeterPanel.tsx:162-166`)の間。C 面 4px を入れて 714 |
| 外枠 中(H3 と H5 の隙間) | 48〜52 | 700 | 同上 |
| 下段 H5 | 52〜100 | **683** | CRT のくぼみ(`headerGeometry.ts:88`、x=346〜680)と「みんなの軽減表」のくぼみ(`:121` `nOut` at MW−502 = 687、左下の角が 687・左上の角が 697)の間 → §D7 で CRT を 4px 短くして 683 |
| 外枠 下 | 100〜102 | 700 | 同上 |

- `headerGeometry.ts` の `basePanels()`(`:60-101`)で、chassis・h3・h5 を切れ目で左右 2 枚に分ける(`armor/geom.ts:42` の `clipHalf`)。くぼみ・ボルト・彫り線・継ぎ目・傷の範囲は中心の x で左右に振り分け、`seed` は元の形で固定する(見本 engine.js の `splitSpec`)。h1・h2 は左、h4 は右。
- **左の半分は動かさない**(伸縮線より左 = 今と同じ)。**右の半分は全点を (MW − 1189) だけ平行移動する**。`stretchPlaced`(`armor/stretch.ts:61-70`)は `sx` より大きい点だけを動かすので、右の半分は `sx` をその板の最小 x より小さく(例: `p.x − 1`)した枠で伸ばす = 平行移動になる(H5 の右半分は x=683 の点を持ち、`sx=700` のままだと歪む。`headerLayout` の既存の「MW から直接置く」方針 `headerGeometry.ts:114-116` と同じ考え方)。
- `headerLayout(MW)` が返す `panels` の順序は下から [基板の光 → 下の板 → chassis 左 → chassis 右 → h1 → h2 → h3 左 → h3 右 → h4 → h5 左 → h5 右](`MilspecArmor.tsx:51-54` は配列順に描く)。`MilspecHeaderV11.tsx:52` が `MilspecArmor` に渡す枠は `sx: 9999` にする(全て MW 基準で置き終わっているので、装甲側で二度と伸ばさない。幅の計測が 1 コマ遅れても形が歪まず、ずれは `relayout.ts:271-298` の `whenSettled` が今どおり吸収する)。
- 上の板の切れ目の見た目(見本 v3 `machinedEdge`): ワイパー(1.6px の暗い帯)+ C 面の加工目(0.35px の斜線を 1.6px 間隔)+ 稜線の細い光。`PanelSpec` に `extra?: string`(汚しの後に足す生 SVG)を追加して載せる。

### D2. 下の板(引き出される板)= 新しい描画種 `drawer`

- 位置: **右の板に付く**。区画座標で `x0 = cut − 60`(左へ隠し代 60)〜 `x1 = (MW − 1189) + 714 + 60`。高さ 0〜102。見える窓は帯ごとに `[cut, cut + (MW − 1189)]`。1489 の画面: サイドバー開 = 窓 0(完全に隠れる)/ 閉 = 276。**1920 / 2560 の画面ではサイドバーを開いていても窓が 431 / 1071px あり、網と基板は常時見える**(§5 Q1)。
- 台(見本 `CARRIER`): 上 0〜6 / 中 46〜54 / 下 98〜102 の 3 本の帯を `armorSVG` の長方形(b=1.6、影 0)で描く。色は `drawerTone(1.00)` = sec と chs を 0.8 で混ぜたもの(見本 engine.js `drawerTone`)。
- 窓(見本 `FIELDS`): 6〜46 / 54〜98。見本 v3 `meshDefs` / `meshField` のとおり:
  - 網: 20×10 のパターン(影の複製 → 「＼」暗 → 「／」明 → 結び目)。穴は塗らない(= 背景動画が透ける)。
  - 溶接した平鋼の枠(上下 3px、`stl-sh`)+ ビード(14px おき)。
  - 汚れ/傷 = 2.0: 結び目の下側の汚れ(パターン)・枠の下辺に寄る汚れ帯 + しずく・ワイパーが通る帯の油の黒ずみ(下半分寄り)と磨かれた横筋・進行方向の抉り傷(2+2×2.0 = 6 本)・ビードの隙間だけの錆と亜鉛の白い吹き・ハザード止め脇の指紋状の曇り・枠の縁の欠け(`weather.ts:12` の `chipsSVG` をそのまま使う)・固定側の角の汚れ・縁が休む 2 か所のつやと黒ずみ。
  - 暗さ = 1.00: 窓全体に黒 0.42 を重ねる。
  - 台の厚み: 窓の上の縁の影(4px)と下の縁の光。
- 中央の鋼レール(y 47.6〜52.4、`stl-fl`)、ハザードの止め(`stopBlockSVG` 'hazard'、`hz` パターン = `--ma-warn` の斜め縞)、案内ローラー(止めの内側 +15、台座 + `stl-nut`)、ローラー周りの弧の傷。
- 「縁が休む所」= 左の上の板の切れ目が止まる 2 か所(区画座標): サイドバー開 = `cut`、閉 = `cut + SIDEBAR_SPAN / scale`。下の板はこの 2 か所につや・黒ずみ・指紋を置くので、`headerLayout` は `MW` に加えて `{ sidebarOpen, scale }` を受け取り、`MW_open = sidebarOpen ? MW : MW − SIDEBAR_SPAN / scale` から 2 か所を出す(`headerGeometry.ts:202-203` の `openCarriageX` と同じ発想。`useMilspecHeaderScale()` が両方持つ: `MilspecLayout.tsx:96`)。
- 上の板の縁が下の板に落とす影 = 1.00: 帯ごとに「縁のすぐ下 3.5px・黒 0.9→0」と「穴の底へ 18px・黒 0.5→0」の 2 層を、左の切れ目の右側・右の切れ目の左側に置く。幅は窓の幅で頭打ち(窓 0 なら影 0)。影は**上の板の半分の `extra` ではなく下の板側**に描く(窓の外へ出ない。見本 `render()` の `data-shadow`)。
- 実装先: 新ファイル `src/components/military/armor/drawer.ts` に `drawerSVG(spec: DrawerSpec, pal: ArmorPalette, id: string): string`。`armor/types.ts` の `PlacedPanel.spec` を `PanelSpec | DrawerSpec | GlowSpec` にし、`MilspecArmor.tsx:51-54` は `kind` で描き分ける。`stretchPlaced` は `kind` 付きの spec を素通しする(動かさない)。
- 色: 見本の直書き色(`#9aa3a9` 明の帯・`#565e64` 暗の帯・`#b8c0c5` 結び目・`#dfe5e9` 稜線 等)は **`--ma-drw-*` トークン**にして `military.css` の dark(`:174-211`)と light(`:282-318`)の両方に入れる(`readPalette` `armor/palette.ts:5-21` に読ませる)。light の値は作る人が決め、masaya が実機で確認(§4)。

### D3. 奥の光 = 新しい描画種 `glow`(基板 a)

- 位置: 下の板のすぐ下(配列で前)。窓(6〜46・54〜98、枠の内側)の形で `clipPath`。基板の長さは窓の長さ(MW に応じて伸びるが、部品(チップ・パッド・配線の折れ)は **240px ごとの繰り返し**で置き、伸ばさない)。
- 中身(見本 v3 `GLOWS.a`): 暗い緑の基板(`--ma-pcb`、`military.css:202`)・シルクの縦線・銅の配線(`--ma-cu`、太さ 2.2 の縁 + 1.3 の芯)・金のパッド(`--ma-gold`)・黒いチップ(型番 `LP-0418`・足)・基板全体の緑のにじみ(`glow-g`)。**配線は `MilspecFxLayer` と同じ `path.milspec-trc[data-trace="drw:1"〜"drw:6"]` として置き**、光の粒は既存エンジン `pulse()`(`fx/engine.ts:56`)で走らせる(見本の CSS アニメは使わない。既存の配線光と同じ言葉・同じ見た目)。
- 粒の出し方: 専用のタイマー(0.9〜2.2 秒おきに 1 本、`len: 9`、`speed: 3.4`、`cls: ''`)を `MilspecHeaderV11` の effect に置く。**`startAmbient` の抽選表 AMB(`fx/engine.ts:242`、`h3` 0.4 / `h5a` 0.3 などが入っている)には入れない**(ほかの経路の頻度を薄めない)。出す条件 = `isFxActive()`(`:17-22`。動きを減らす・タブ非表示・電源 off では出ない)かつ 窓幅 > 0。
- 光の強さ = 0.55: 基板のにじみ・パッド・チップのハイライトを入れた `glow` の `<g opacity>`。電源 off(`html[data-ms-power="off"]`)では `opacity: 0`、電源投入でランプと同じ頃(`lampSequence`)に 300ms で点く(CSS transition。`milspecPower.css` に 1 行)。
- 網の帯の縁の裏からの光(見本 `data-rim`): 基板の**静的なにじみ**(楕円 2 つ)をぼかし(`feGaussianBlur` 6)たものをマスクに、帯の両縁の線(パターン `rp`)を `--ma-on` で残す。**粒の動きには追従させない**(マスクは下の板の静的 SVG に 1 回描くだけ。毎フレームの再計算を起こさない = §3 D9)。
- 動きを減らす設定: 粒なし、にじみと帯の縁光は点いたまま(見本と同じ)。

### D4. 透けの前提(暗幕 0.88 のまま)

- 網の穴は何も塗らない。ヘッダー区画自体に背景は無く(`military.css:1257`)、装甲は `z-index:-1`(`:1309`)、背景動画は `position:fixed; z-index:0`(`:1278`)で区画より下。よって穴 → 暗幕 → 動画の順に見える。電源 off の暗幕(`milspecPower.css:7`)もそのまま効く。
- 基板の光は装甲 SVG の中(暗幕より上)なので、0.88 でも見える(見本 v3 で実証)。

### D5. 開閉(relayout)との接続: 段違いの継ぎ目

- 今: `seamOf`(`relayout.ts:361-368`)がヘッダーに `700 × hs` の 1 本線を返し、`splitZone`(`:188-222`)が `clip-path: inset(...)` で左右に切る。
- 新: ヘッダーの継ぎ目は **帯ごとの階段** `{ x, y0, y1 }[]` = D1 の表 × hs。`splitZone` は継ぎ目が配列のとき `clip-path: polygon(...)`(階段の多角形。`clip-path: path()` ではない)で左右を切る。左の複製 = 階段より左、右の複製 = 階段より右(`CLIP_PAD` 16 の外側余白は今どおり)。通気口・フッターは今の `inset` のまま。
- 右の複製に入るもの = 右の板 + 下の板(どちらも画面に固定)。左の複製 = 左の板だけ。これで動きの途中に「上の板の切れ端」が窓に残らない(§2 失敗)。
- `edgeFrames`(`:167-170`)はヘッダーでは今も使われない(継ぎ目 ≥ 移動量)。変更なし。
- 複製の中の `data-trace`(`drw:*` も)は今どおり外す(`:39`、`:157`)。動きの約 500ms 間、複製の基板の粒は止まって見える(許容。本物に戻った瞬間から再開)。
- `PROBES.header = '.milspec-mlv'`(`:30-32`)は右端基準なので今のまま。

### D6. 縮小率(`--ms-hs`)との関係

- 下の板は `.milspec-hs-box`(`military.css:1260-1264`)の中で一緒に縮む。窓幅は区画座標で `MW − 1189`、サイドバーの開閉で変わる量は `SIDEBAR_SPAN / scale`(`headerGeometry.ts:16-22`、Task 4 で確定済み)。
- 1489 未満の画面(例 1280: scale ≈ 0.844)では、開 = 窓 0、閉 = 窓 327(区画座標)。見本の値を使った設計は全てこの式で出す(固定値 276 を書かない)。

### D7. 切れ目の両脇の余白(見本の懸念の解決)

- 上段: NET の文字の右端(≈708)〜 切れ目 714 〜 C 面 718 〜 DTG/時計 721。余白はあるが 3px。変更不要。
- 下段: CRT のくぼみを **4px 短く**する(`headerGeometry.ts:88` `chamRect(334, 40, …)` → `330`、`:162` `crt.w: 328` → `324`。`MilspecCrt` は親の 100% を埋めるので追随 `PartyOps.tsx:101-103`)。切れ目 683、右の板の C 面 683〜687、軽減表のくぼみの左下の角が 687。**軽減表のくぼみは動かさない**(見本 v3 は 3px 右へずらしていたが、その領域は別件で検討中。§5 Q2)。
- H3 の継ぎ目線と光の経路 `h3`(`headerGeometry.ts:78`、`:167`): 左の板の中で終える(`M 630 43 H 706`)。右の半分に継ぎ目線は置かない。
- H5 の継ぎ目線 `M 690 5.6 H MW−514`(`:116`)と光の経路 `h5b`(`:170`): **廃止**(その場所は下の板の窓になる)。`headerGeometry.test.ts:25-27` の `h5b` の期待は削る。
- `h5` の `wear`(`:91` `[MW−150, 26, 80, 5]`)は右の半分に、`[150, 28, 110, 4]` は左の半分に振り分ける。

### D8. 値(masaya 決定の写し。実装は定数として `armor/drawer.ts` 先頭に置く)

`DRAWER = { shadow: 1.00, dirt: 2.0, dark: 1.00, glow: 0.55 }`。見本 v3 の各つまみの意味そのまま(影 = 2 層の不透明度の係数、汚れ = 個数と濃さの係数、暗さ = 黒 0.42 × 1.00 と台の色の混ぜ率 0.8、光 = `<g opacity>`)。

### D9. 性能

- 下の板は **静的な SVG 1 枚**(パターン・マスク・ぼかしは描いたときに 1 回評価)。`MilspecArmor` は `contentKey`(`MilspecArmor.tsx:16`)が変わらない限り描き直さない。
- 動くのは基板の `glow` SVG の中の粒(エンジンが WAAPI で `stroke-dashoffset` を動かす。ほかの経路と同じ)だけ。`glow` SVG にはぼかしフィルタを**置かない**(粒が走るたびにフィルタ付き SVG 全体が再ラスタされるのを避ける)。にじみは静的な放射グラデーション。
- 検収: Chrome DevTools の Rendering → Paint flashing で、静止中(粒が走っていない間)にヘッダーが塗り直されないこと。粒 1 本あたりの塗り直しが `glow` SVG の矩形(窓の大きさ)に収まること。

### D10. 右端基準・着後位置合わせ禁止(継承)

## 4. 制約

- CSS ルール(`.claude/rules/css-rules.md`): `backdrop-filter` 直書き禁止 / `clip-path: path()` 禁止(`polygon()` と `inset()` は可)/ CSS `zoom` 禁止。
- 動きは transform / opacity / clip-path(inset・polygon)だけ。毎フレームで幅や属性を書き換えない。
- SVG の id は画面内で一意(`armorSVG` と同じく呼ぶ側の `id` を接頭辞にする)。複製(`cloneNode`)で id が重複するのは今の装甲と同じ状況で許容(隠した本物が定義を持つ)。
- 新しい色は全て `--ma-*` トークン経由(直書き禁止・`feedback_css_token_verify_before_use`)。dark と light の両方に入れる。
- 画面写真の検収は 1489×679・deviceScaleFactor 2.58(本人環境)で、見本 v3 の「閉(引き出し)」「開(収納)」「開閉を再生」の途中のコマと見比べる(`feedback_visual_fidelity_requires_screenshot_diff`)。多数派の 1920×1080 / DPR 2 でも 1 回確認する(窓が常時見える前提の確認)。
- push 前ゲート: `npm run build`(tsc -b 厳密)+ `npm run test:gate`。開発中は対象テストだけ `npx vitest run <path>`。
- ユーザー向け文言は増やさない(下の板・基板に文字があっても刻印の英数字だけ。i18n なし)。

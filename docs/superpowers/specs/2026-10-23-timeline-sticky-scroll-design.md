- 日付: 2026-10-23
- 対象: PC の `/miti` 軽減表(`isMobileTimeline === false`)。スマホは変えない
- 状態: 設計のみ(アプリのコードは未変更)。実装は §10 の段階ごとに進め、各段階の合格条件を満たしてから次へ進む
- 書式: 確認した事実には `file:line` を付けた。確かめていないことは「未確認」と書いた

## 0. 結論(先に要点)

1. **本文の固定 = 案 A 改(固定ペイン + 入れ物の幅を中身いっぱいにする)を採用する。** 情報列 6 つ(フェーズ・ラベル・時間・攻撃・元のダメージ・軽減後)を、同じスクロールの入れ物の中にある `position: sticky; left: 0` の不透明なペインへ移す。前回の主因だった「sticky が入れ物の幅(= 画面の幅)の中でしか止まらず、端までスクロールするとずれる」は、入れ物(`sheetContainer`)に中身と同じ幅を持たせて根本から消す。座標の系は 1 つのまま変えない。
2. **xRatio(メモ・カーソルの横位置の割合)の分母を、入れ物の幅から切り離す。** 分母は今と同じ値(スクロールの入れ物の内側の幅)を、別の場所から測る。入れ物を広げても保存データの意味は変わらない。
3. **見出しとボタンの欄は、入れ物の外に置いたまま、CSS のスクロール連動アニメーション(scroll-driven animations)で動かす。** スクロール位置から直接位置を決めるので、ブラウザが同じコマで描く(1 拍遅れが原理的に起きない)。対応していないブラウザでは今の JS の追いかけ方式にそのまま戻る(今より悪くはならない)。入れ物の中へ移して sticky にする案(H1)は、MIL-SPEC のボタンの欄が表の枠より左右 10px はみ出す今の見た目(`milspecTable.css:21-23`)を保てないので、予備の案にする。
4. **見出しとボタンの欄の「動く側」は、固定列の右端から始まる「窓」(はみ出しを切る箱)の中に入れる。** 前回の「ジョブのアイコンが見出しの上にはみ出す」は、上に不透明な覆いをかぶせる方式だったのが原因。今回は切り取りなので、覆いの色合わせが要らない。
5. 進め方は「変更前の記録 → 小さな試作で可否判断 → 本番」。機械で合否が分かる条件を段階ごとに付ける(§10)。
6. ユーザーに聞くのは見た目の選択だけ(§11)。MIL-SPEC の横スクロールバーの案と、固定列の境目の見た目。

## 1. 目的と範囲

### やること
- (目的 1)横スクロールで、左の情報列 6 つを固定し、右側(軽減のレーン、またはスプシの技の列)だけを動かす。本文・見出し・ボタンの欄の 3 か所すべて。
- (目的 2)横スクロールで見出しとボタンの欄が 1 拍遅れる問題を、後から追いかける作りをやめて直す。
- (目的 3)MIL-SPEC の横スクロールバーを世界観に合う形にする。縦バーは非表示のまま(`military.css:1466`)。
- (目的 4)既存の機能を壊さない。§4 の回帰チェックリストを変更前に自動で記録し、変更後に同じ結果になることを機械で確かめる。

### やらないこと
- スマホ(`MobileTimelineRow`・`isMobileTimeline` 経路)の変更。
- 「自由スクロール」(末尾のメンバー列を固定列の真横まで引けるよう、右に余白を足す機能)。前回これがずれを表面化させた(`265bff04`)。今回の作りなら安全に足せるはずだが、今回は入れない。
- 保存データの形式の変更(メモ `PlanMemo` の `xRatio`、共同編集のカーソルの送信内容)。
- 縦スクロールの仕組みの変更(縦の座標・`scrollTop` の意味はそのまま)。
- 表の DOM を 1 マス 1 要素にすること(性能の方針どおり、行のマスは 1 メンバー 1 要素のまま)。

### 6.1 xRatio の分母(保存データの意味を変えない)
- 今: 分母 = sheetContainer の幅(`Timeline.tsx:836-850`)。実測で、スクロールの入れ物の内側の幅と同じ(`memberX.ts:59-65`)。

### 6.2 sheetContainer の幅(sticky が止まる範囲)
- sheetContainer の幅 = max(中身の幅, 入れ物の内側の幅)。今の `md:min-w-full` は残し、幅を足す。
- 中身の幅は、行のセルの幅と**同じ式**から作る(固定列の幅 + メンバー列の幅の合計。スプシは列数 × `--sheet-col-w`)。式の出所は 1 か所にする。どの関数が行のセル幅を出しているかは未確認(`TimelineRow.tsx:654-670` 付近)。計画の段階で確かめる。
- 合格条件: `sheetContainer.offsetWidth === 最初の行(レーン側).offsetWidth`、かつ中身が画面より広いとき `=== scroller.scrollWidth`。ふつう/スプシ・人数・列の折りたたみ・メンバーの非表示の全組み合わせで確かめる。

### 6.3 固定列の幅
- `--frozen-w` = フェーズ(または折りたたみ幅)+ ラベル(または折りたたみ幅)+ 時間 + 攻撃 + 元のダメージ + 軽減後(前回の `infoPaneWidthCss` と同じ式・`9387f140`)。式は 1 つの関数で作り、ペイン・行の空き・見出しの窓・ボタンの欄の窓・`scroll-padding-left` で同じ値を使う。
- スクロールの入れ物に CSS 変数で置く(子へ引き継ぐ)。見出しとボタンの欄は入れ物の外なので、共通の親 `.glass-panel` に置く。

### 6.4 マウスの位置 → 表の中の横位置(固定列を考えた変換)
今はどこでも `clientX - sheetRect.left`(= スクロール込みの中身の座標)。固定列があると、固定列の上を指したときにこの式は「固定列の裏に隠れたレーン」を指してしまう。そこで変換を 1 つの純粋な関数にまとめる。

```
toSheetX(clientX):
  x画面 = clientX - 入れ物の内側の左端
  x画面 < 固定列の幅  → 戻り値 = x画面            (情報列の座標。スクロール 0 のときの中身の座標と同じ)
  それ以外            → 戻り値 = clientX - sheetRect.left (今と同じ)
```

使う所(全部、grep で洗い出した `clientX` の利用先):
- メモの作成 `Timeline.tsx:1133`(固定列の上は作らない、が横に動かしても守られる)。

- メモのドラッグ `MemoOverlay.tsx:99`(離した位置を `toSheetX` で求める)。

スクロール 0 のときは、どの場合も今と同じ値になる。保存・送信する値の形は変えない。

- 行: `milspecTable.css` の `[data-time-row] > :nth-child(N)`(`:123, 128, 139-141, 149-166`)を、情報の側だけに効くよう `[data-time-row][data-row-part="info"] > :nth-child(N)` にする。レーン側では最初の子が空きになり、番号がずれるため。

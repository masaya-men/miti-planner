# ハウジング 探すページ タグ検索(AND対応) 設計書 (2026-07-27)

## 背景

現状「探すページ」のタグ絞り込みは、左パネルの「テーマ」ドロップダウンだけが UI として存在し、公式/季節/初心者タグには絞り込み UI がなく、個人タグ(ハウジンガータグ)は絞り込みに使えなかった(実装済みの `PersonalTagFilter.tsx` はどこにもマウントされていない孤児コンポーネント)。

既存の「テーマ」だけの絞り込みは OR 方式(選んだタグのどれか 1 つでも一致すれば表示)だが、ハウジンガータグを同じ OR 方式に混ぜると「初心者向け」+「ハウジンガーたろう」を同時選択したときに初心者向けの家全部+たろうさんの家全部(初心者向けじゃなくても)が混ざって出てしまい直感に反する。この問題を解決しつつ、公式/季節/初心者タグにも絞り込み UI を新設し、全タグ種別(公式/季節/テーマ/初心者/ハウジンガー)を 1 つの新しいタグ検索 UI に一本化する。

## スコープ

- 対象: 探すページ (`BrowsePage.tsx`) PC 版・スマホ版の両方
- タグ絞り込み UI を新設し、既存の左パネル「テーマ」ドロップダウン (`FilterPanel.tsx`) は削除して統合
- 対象外: ツアーページ/お気に入りページ/管理画面のタグ関連 UI (変更なし)、個人タグの新規作成・通報フロー (既存のまま)

## 決定した挙動

### 1. 配置・切り替えの仕組み (PC)

- 中央パネル上部の「一覧|マップ」トグル (`BrowseViewToggle.tsx`) に 3 つ目のタブ「タグ」を追加する (`HousingBrowseView` 型を `'list' | 'map' | 'tags'` に拡張)。
- 「タグ」タブを選ぶと、地図の DC/ワールド選択画面 (`WorldSelectGate.tsx`) と同じ見せ方で、中央パネルの中身がまるごとタグ選択画面に切り替わる。一覧・マップと同じ「ビュー切り替え」の仕組みを踏襲し、ポップオーバーやモーダルにはしない。

### 2. タグ選択画面の構成

- 上から「ハウジンガー」セクション: 登録されている個人タグ (ハウジンガー) を全員分チップで並べる (検索ボックスは設けない。人数が増えたらスクロールで対応)。折りたたみ可能。
- その下に「タグ全部」セクション: 公式・季節・テーマ・初心者 (計 48 種、今後増減あり) を 1 つのチップ羅列にまとめ、種別ごとに軽い区切り線・小ラベルを添えて見分けやすくする。折りたたみ可能。
- どちらのセクションも複数選択可 (ハウジンガーも複数人選択可)。

### 3. 選択〜絞り込みの操作フロー

- チップをクリックしても即座には絞り込まれない。選択中は該当チップが光る/塗りつぶされる見た目で選択状態を示す (個数バッジ等は出さない)。
- 選択中は、現在の選択条件でヒットする件数をリアルタイムでプレビュー表示する。
- 「この条件で絞り込む」ボタンを押した時点で選択を確定し、実際のフィルタ結果に反映する。反映と同時にビューは常に「一覧」に戻る (「マップ」には戻らない。地図はワールド 1 つに絞られていないと表示できないため)。
- 「絞り込む」を押さずに一覧/マップタブへ直接移動した場合、選択中のチップは破棄されず保持される (次にタグタブを開くと同じ選択状態に戻る)。業界標準の絞り込み UI (Airbnb 等) に倣い、明示的な操作なしに選択を失わせない。
- 選択をリセットする「クリア」を絞り込むボタンの近くに設置する (選択を空に戻すだけ。実際に適用中のフィルタを解除するのは既存の「フィルター解除」ボタンの役割のまま)。

### 4. 絞り込みロジック (AND/OR)

- ハウジンガー以外 (公式/季節/テーマ/初心者) は選んだタグのどれか 1 つでも一致すれば OR 一致 (現状の「テーマ」と同じ挙動)。
- ハウジンガーを 1 人以上選んだ場合は、「非ハウジンガータグ側の条件を満たす (選んでいなければ無条件で満たす)」かつ「選んだハウジンガーのうち少なくとも 1 人の家である」の組み合わせ (AND)。
- ハウジンガーを複数人選んだ場合、その中では OR (誰か 1 人の家であればよい)。

### 5. スマホ版

- 左パネルがまるごと非表示のスマホでは、ボトムナビの「フィルター」ボタンから開くシート (`HousingFilterSheet.tsx`、中身は `FilterPanel` をそのまま流用) 内で、今まで「テーマ」があった位置を「タグで絞り込み」に差し替える。
- タップすると (PC 同様のフルスクリーン切り替えではなく) 既存の `FilterDropdown` と同じ感覚でその場にインライン展開する。中身は PC 版と同じ「ハウジンガー」「タグ全部」の 2 セクション+件数プレビュー+絞り込むボタンを流用する。
- 「絞り込む」を押すとその場で折りたたまれて選択が確定するだけで、シート自体は閉じない (他のフィルター項目を続けて調整できるように)。ユーザーはシートの閉じるボタンを押して初めて一覧画面に戻る。

### 6. 左パネルの整理 (PC)

- `FilterPanel.tsx` から既存の「テーマ」`FilterDropdown` を削除する (スマホも同じコンポーネントを共有しているため自動的に両方に反映される)。

## 技術的な注意点

- `applyFilters.ts` の現在のタグ判定は `filters.tags.some(...)` による単純 OR。ハウジンガー (`personal_` prefix、`isPersonalTagIdFormat` で判定可能) とそれ以外を分離し、(非 personal タグ側 = OR or 未選択なら真) AND (personal タグ側 = OR or 未選択なら真) の形に拡張する。
- 個人タグ・公式/季節/テーマ/初心者タグは既に同じ `tags: string[]` 配列に混在格納されており、Firestore スキーマ変更は不要。
- ハウジンガーチップの一覧は既存の孤児コンポーネント `PersonalTagFilter.tsx` (検索ボックス付き) をそのまま使わず、新規に「全員をチップ表示」する一覧コンポーネントを作る (既存コンポーネントは検索型 UI のため今回の要件と異なる。ただしチップ+選択トグルの実装パターンは参考にできる)。
- 選択の「保留状態 (pending)」はグローバルストア (`useHousingFilterStore` の `tags`) とは別に、コンポーネントローカルか専用の一時状態で保持し、「絞り込む」押下時にのみ `tags` へ反映する。
- `PersonalTagFilterLink.tsx` (個人タグちょうど 1 件のときに「◯◯さんのページを見る」リンクを出す機能) は `tagIds.length === 1` の判定のみで動いているため、今回の変更 (複数選択対応) でも無改修でそのまま動作する。
- 新規 UI 文字列は全て i18n キー経由 (`.claude/rules/i18n.md` 準拠)。
- PC/スマホで同じ「タグ選択画面」の中身 (2 セクション+件数プレビュー+絞り込むボタン) を共有コンポーネント化し、PC は `BrowsePage` 中央パネルのビュー切り替えとして、スマホは `HousingFilterSheet` 内のインライン展開として、それぞれ別の入れ物で表示する。

## スコープ外

- 公式/季節/初心者タグの新規追加・編集 (既存データ・登録フローは変更なし)
- ハウジンガータグの新規作成・通報フロー (変更なし)
- タグタブに件数バッジを表示する対応 (見送り。チップの光り方で選択数を示す)
- ハウジンガーチップ一覧の検索ボックス (見送り。人数が増えた場合の対応は別途検討)

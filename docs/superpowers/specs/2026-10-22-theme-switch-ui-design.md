## 1. 目的(なぜ)

MIL-SPEC テーマを一般公開するとき、ユーザーが迷わず「見た目」を切り替えられ、切り替えた瞬間とその後の操作で「物理的な機械を操作している」質感が崩れないようにする。

- 今の標準ヘッダーの切替ボタンは、ホバーすると白地に白いアイコンになって見えない。ツールチップもブラウザ標準の箱になっている。
- 「MIL-SPEC」は開発内のコードネームで、ユーザーには意味が通じない。
- MIL-SPEC 側の切替レバーは「電源を入れる」という表現になっている。真っ暗で、何の部品なのか分からない。
- 切り替え直後、画面全体が一度に明るくなる。順番のある「起動」の遊び心が欲しい。
- MIL-SPEC でサイドバーやヘッダーを開け閉めすると、全区画が同時に動く。さらにヘッダーは、サイドバーの開閉で滑らずにその場で幅が変わる。そのため「板が伸びた」ように見え、物理パネルの質感が壊れる。

## 2. ゴール / やらないこと / 失敗とみなすこと

ゴール
- 標準・MIL-SPEC のどちらでも、切替の部品の説明は「見た目を切り替える」の一語だけにする(テーマ名は出さない)。
- 標準のボタンが、ホバー中も見えて、LoPo のツールチップを出す。
- MIL-SPEC のレバーは今の形と動きのまま、中の機械が見えて光が走るようにして、ひと目で「動かせるスイッチ」と分かるようにする。
- MIL-SPEC に入ったときは、暗転 → フレーム(サイドバー・ヘッダー側)に光が走って点灯 → タイムラインが蛍光灯のようにチカチカして点く、の順で立ち上がる。
- MIL-SPEC の区画の開閉は、時間差で「板がそのままの大きさで滑り込み、はまる」動きにする。

やらないこと
- テーマに名前を付けること(「タクティカル」等は不採用・masaya 判断)。
- 標準テーマの開閉の動き(Layout.tsx の framer-motion)を変えること。D は MIL-SPEC だけ。
- 標準へ戻るときの切替演出を変えること(今の `runTransition(..., 'theme')` のまま。私の判断)。
- 一般公開(WIP ゲートの撤去)。公開はスプシモードと一緒に大型アップデートで行う。

失敗とみなすこと(動いても不合格)
- 開閉の最後に、ボタンや部品が「位置を合わせるために」ずるっと動く。物理ボタンは位置調整で滑らない(masaya 明言)。
- ヘッダー・タイムラインの区画が伸びたように見える。
- 新しい部品が MIL-SPEC のほかの部品と並べて質感で浮く(見本はあくまで下書き。品質は本番の MIL-SPEC 水準が条件)。
- ユーザー向けの文言に「電源」「MIL-SPEC」が出る。

## 3. 決まったこと(masaya の決定)

### A. 標準ヘッダーの切替ボタン(`src/components/military/MilspecStyleToggle.tsx` を使っている箇所)
- 形は今の六角ボルト+四隅のアイコンのまま(A1)。
- 不具合の原因(確認済み): ボタンは `hoverInvert`(`hover:bg-app-toggle hover:text-app-toggle-text`、ConsolidatedHeader.tsx:56)で反転する。ところが svg 側の `text-app-text-muted group-hover:text-app-text` が文字色を上書きするので、白地に白になる。svg は親の文字色を継ぐようにする(military のときのアクティブ色は残してよい)。
- ツールチップは、ほかのヘッダーボタンと同じ `Tooltip` コンポーネント(`src/components/ui/Tooltip.tsx`)を使う。素の `title` はやめる(aria-label は残す)。
- 文言は向きに関係なく「見た目を切り替える」の1つ。新しいキーを 5 言語で追加する(下の i18n を参照)。

### B. MIL-SPEC のレバー(`src/components/military/header/ModeLever.tsx` + `milspecH4.css`)
- 形・大きさ(36×30、headerGeometry の `decor.h4.lever`)・ドラッグ/クリック/キーボードの動き・開いた直後に自動で下りる動きは今のまま。
- 見た目は v2 見本の **L1** にする。
  - つまみの両側に、ガラス窓越しに歯(ラック)が見える。
  - ガラス窓の縁が緑(`--ma-on`)にうっすら光る。
  - 溝の中を光が下から上へ流れ続ける(上げると標準に戻る向き)。待機時は 1 周約 1.8 秒、ホバー中は約 0.9 秒。
  - LED・ハザード模様・銀のつまみは残す。
- 動きを減らす設定のときは、流れる光を止めて縁の光だけ残す。
- 説明(title / aria-label)は「見た目を切り替える」。今の `milspec.hdr_lever_power_on`(電源を入れる)と `app.theme_style_to_standard` の出し分けはやめる。MIL-SPEC 内の title は `MilspecTitleTooltip` が LoPo のツールチップに置き換える(MilspecLayout.tsx に既にある)。

### C. MIL-SPEC に入ったときの立ち上がり(`src/components/military/power/*`)
- 順番: ① 真っ暗(今の「電源 off」の暗幕) → ② サイドバー(上から下)とヘッダー(左から右)に光の帯が走り、帯が通ったところから明るくなる。ランプはその後で順に点く(今の `sequenceLamps`) → ③ タイムライン(workspace 区画)が蛍光灯のように 2〜3 回チカチカしてから点く(index.html の C3)。
- 長さは見本 C3 の 1.0 倍。見本では ② が約 250〜1000ms、③ が 1150ms 開始で約 900ms。
- 「電源」という仕組みは内部の名前として残してよい(`data-ms-power`・`powerOn` など)。ユーザーに見える文言からだけ消す。
- 今ある演出(配線を光が駆け抜ける `burst`、CRT の起動、メーターの転がり)は残し、②③ の順番に合わせて時刻を調整する。
- 動きを減らす設定のときは、今と同じく演出なしで即点灯。

### D. MIL-SPEC の区画の開閉(`src/components/military/relayout.ts`、`MilspecLayout.tsx`)
1 段目と 2 段目を時間差で動かす(「ずらす間」既定 80ms、1 つの動き既定 420ms、今の「少し行き過ぎて戻る」keyframe は残す)。

- サイドバーを閉じる: サイドバーだけ左へ抜ける → 下地(背景動画)が見える → ヘッダー・通気口・レール・タイムライン・フッターが左へ滑り込む。
- サイドバーを開く(私の案・masaya 了承): ヘッダーたちが右へよける → 下地 → サイドバーが左から入る。
- ヘッダーを開く: 通気口(取っ手)とタイムラインが一緒に下がる → 上に下地が見える → ヘッダーが上から下りる。
- ヘッダーを閉じる(私の案・masaya 了承): ヘッダーが上へ抜ける → 下地 → 通気口とタイムラインが上がる。

伸びたように見せないためのルール(絶対):
- **右端を基準に置かれた部品は、画面上で一度も動かない。** ヘッダーの H3 の時計と ID、H4 一式(レバー含む)、H5 の mainstream・gear・sort、通気口の hazR・pnX。どれも headerGeometry / ventLayout で `MW - n` の位置にあり、開閉の前後で画面上の位置は同じ。
- **左端を基準に置かれた部品は、1 枚の板として滑る。** 板の左端(縁)が見えたまま動く。着いてから位置を直す動きは禁止。
- **幅で伸び縮みする所(H3 メーターの中央、H5 の継ぎ目、通気口の溝)** は、左の板が上を滑って重なったり離れたりする場所として見せる。伸び縮みしているようには見せない。
- タイムライン・フッター・レールは、その形のまま滑る(中身は左寄せなので、はみ出した右側は画面の端に隠れる)。
- ヘッダーの開閉で縦に動くとき、タイムラインのはみ出した下側はフッターの下と画面の外に隠れる。

通気口の台車(masaya 案):
- 幅で位置が変わるのは、通気口の真ん中のかたまり(格子 `milspec-lb-row`・取っ手 `milspec-pull`・PULL の文字。ventLayout の `xb0 = MW/2 - 190`・`pull.x = MW/2 - 26`)だけ。これをレールに乗った台車にする。
- サイドバーの開閉に合わせて、台車がレールの上を走って新しい位置に着く。画面上の移動量はサイドバーぶんの半分(1489 基準で約 138px)。少し遅れて動き出し(既定 60ms)、一定の速さで走り、最後にカチッと止まる。走っている間は台車のランプがオレンジ(`--ma-warn`)に点き、車輪が回る。
- **レールは台車が動く範囲だけを描く。** サイドバーを開いた位置と閉じた位置の台車の両端を囲む長さで、両端に止め金具(ハザード模様)を付ける。画面の大きさ(ヘッダーの縮小率 `--ms-hs` を含む)からその場で計算し、ぴったりにする。計算できない場合だけ長めの余白で描いてよい。レールは画面に固定され、板と一緒には動かない。
- 取っ手を引いてヘッダーを開け閉めする今の操作(`milspec-pull` の tug)は今のまま。

ヘッダーの縮小率 `--ms-hs`(私の判断):
- 今は区画の実幅から `headerScale(w)`(幅 1189 未満で縮小)を出している(MilspecLayout.tsx:78-85)。1489 の画面でサイドバーを開くとちょうど 1189 で縮小率は 1 になり、開閉で変わらない。1489 より狭い画面だと、開閉で縮小率が変わり、部品の大きさが変わってしまう(=「伸びた」に見える)。
- そこで、縮小率は「サイドバーを開いたときの幅」で決め、閉じても同じ値を使う。閉じて広がった分は、ヘッダーの伸縮部(中央)が受け持つ(`layoutMW` は実幅 ÷ 縮小率)。こうすると、どの画面幅でも開閉で部品の大きさは変わらない。
- 画面幅そのものを変えたとき(ウィンドウのリサイズ)は今まで通り縮小率が変わってよい(開閉の動きではないため)。

その他(作る人への補足・私の判断):
- 下地 = 区画の隙間から見えている背景動画(`MilspecBackdropVideo`)。区画が退いた所は透明のままでよい。
- 台車の移動量とレールの長さは、実際の区画幅(実測)と縮小率から両状態の台車位置を計算して出す(固定値にしない)。
- 消すキーを検証している既存テスト(例: `AuxPanel.test.tsx`)は、新しい文言に合わせて書き換える範囲に含める。

キーボード(H / S / F)・フォーカスモード・チュートリアルからの開閉も同じ動きにする(今の `useHeaderCollapseAnimator` / `useSidebarToggleAnimator` 経由)。動きを減らす設定のときは即時に切り替える(今と同じ)。

## 4. 制約
- ハウジング以外の CSS ルール(`.claude/rules/css-rules.md`): `backdrop-filter` の直書き禁止、`clip-path: path()` 禁止。
- CSS zoom 禁止(`feedback_no_css_zoom_scaling`)。
- 動きは transform / opacity / clip-path(inset)で行い、レイアウトの読み直し(幅の毎フレーム変更)をしない。
- 光エンジンが残像の複製を経路として拾わないこと(relayout.ts が今やっている識別属性の除去を維持)。
- 品質の確認: 1489×679・DPR 2.58 で実寸の画面写真を撮り、見本と見比べる(`feedback_visual_fidelity_requires_screenshot_diff`)。開閉は途中のコマも撮って「右の部品が動いていない」「最後に位置合わせがない」を確かめる。
- 本番ビルドの確認は push 前ゲート(`npm run build` + `npm run test:gate`)。
